# 短剧数据管理与分析系统功能说明

## 1. 文档说明

本文档以用户可理解的方式说明短剧数据管理与分析系统 V1.0 的实际功能，用于软件著作权申请和系统验收。仅描述已经存在的功能，不把规划项、未来扩展或内部技术组件表述为现有产品能力。

## 2. 用户认证与权限管理

### 2.1 用户登录

用户通过登录页面输入已分配的账号和密码。后端验证身份后签发 JWT，前端使用现有认证流程访问受保护接口。

系统不开放公共用户注册，也不在文档中提供固定默认密码。

### 2.2 用户角色

系统包含两类角色：

- `ADMINISTRATOR`：在授权范围内执行数据维护、导入、分析计算及管理操作；
- `USER`：查看 Dashboard、基础数据、分析结果、治理信息及报告，并可导出有权访问的数据。

### 2.3 权限控制

前端根据登录状态提供导航入口，后端对受保护接口重新校验身份和角色。匿名访问受保护页面或接口时，应进入登录流程或返回未认证状态。

## 3. 数据管理

### 3.1 基础数据管理

系统管理的基础对象包括：

- 短剧（Drama）；
- 演员（Actor）；
- 导演（Director）；
- 公司（Company）；
- 平台（Platform）；
- 标签（Tag）；
- 短剧与平台、人员、标签之间的关联关系。

用户可以在权限范围内查询、筛选和维护基础资料。系统以明确关系保存主要关联，不以自由文本替代已存在的结构化关系。

### 3.2 数据导入

系统支持 CSV/XLSX 文件导入，包括：

- 文件上传；
- 模板和字段校验；
- 数据行校验；
- 错误记录查看；
- 导入确认；
- 导入任务状态查看。

导入遵守现有数据库约束和业务校验规则，不在本模块中自动推断缺失业务事实。

### 3.3 历史指标与 Revision

系统保存短剧历史运营指标和必要的版本信息，用于按时间截点读取、趋势分析和结果追溯。历史 Revision 不应被当前值无条件覆盖。

## 4. 数据分析中心

### 4.1 指标分析

系统基于已有历史指标展示播放、互动、增长、热度和潜力等已实现指标。页面使用已有分析结果，不在展示层重新定义指标口径。

### 4.2 综合评分

综合评分模块根据固定版本规则生成并保存评分结果，支持查看：

- 总分；
- 分项得分；
- 评分等级；
- 算法版本；
- 分析时间。

评分仅表达规则计算结果，不构成投资、采购或运营推荐。

### 4.3 数据质量分析

Phase 2 Data Quality 模块提供与业务分析相关的持久化质量结果，包括质量评分、状态和规则结果。该模块与 Phase 9 请求时数据治理检查职责不同。

### 4.4 预测分析

Prediction 模块使用已实现的固定 Moving Average V1.0 规则，对下一日累计播放量生成预测，并保留算法版本、分析时间及历史结果。

预测是基于历史数据的规则结果，不代表收益保证或自动运营决策。

### 4.5 异常分析

Anomaly 模块根据确定性规则识别已有指标数据中的异常情况，支持查看异常类型、严重程度、状态、证据和处理信息。系统不使用机器学习模型自动解释异常。

### 4.6 运营行动与解释血缘

系统支持记录运营行动、负责人、状态、评论及历史变化。Explanation 与 Data Lineage 模块用于展示分析摘要、规则版本和来源信息，帮助用户理解结果依据。

## 5. Drama Profile

Drama 360° Profile 以单个短剧为中心聚合已有模块信息，包括：

- 短剧基础资料；
- Performance；
- Quality；
- Trend；
- Risk；
- Operations；
- Explanation 与来源入口。

Profile 属于只读聚合视图，不修改评分、预测、异常、运营行动或解释记录，也不重新计算这些模块的业务事实。

## 6. Operation Analytics

### 6.1 Action Effect

系统读取运营行动及行动前后时间窗口的指标，展示行动完成前后观察到的指标变化和 Availability 状态。

系统仅允许“行动发生后指标发生变化”或“行动与指标变化存在关联”等描述，不判断运营行动导致指标变化，也不输出行动成功、失败或推荐结论。

### 6.2 Lifecycle

系统使用固定、可解释、版本化的规则，将短剧表示为以下生命周期阶段之一：

- LAUNCH；
- GROWTH；
- STABLE；
- DECLINE；
- ARCHIVED。

生命周期判断基于既有时间窗口和指标变化，不使用机器学习分类。

### 6.3 Benchmark

系统对显式选择、同平台的短剧集合执行统计比较，展示统一时间窗口下的指标统计结果。Benchmark 不生成排名、最佳短剧或推荐名单。

## 7. Data Governance

### 7.1 Freshness

检查最新数据时间、数据延迟和更新时间状态，输出明确的质量状态、可用性和 Evidence。系统不自动刷新数据。

### 7.2 Completeness

检查必要字段、指标覆盖、时间序列连续性和关联覆盖，输出覆盖率、缺失项及 Evidence。系统不自动补齐数据。

### 7.3 Consistency

检查关联关系、Weak Reference、Revision 和 `analysis_as_of` 一致性，输出问题数量及 Evidence。系统不自动修复关系或 Revision。

### 7.4 Evidence

Evidence 展示形成治理状态所使用的最小解释信息，例如最新时间、延迟、缺失项和关联问题。Evidence 不复制完整业务对象，也不生成新的业务判断。

## 8. Reporting Center

### 8.1 Report Catalog

报告目录由后端显式 Schema Registry 提供，V1.0 支持：

- DRAMA_CATALOG；
- SCORE_RESULTS；
- DATA_QUALITY_RESULTS；
- PREDICTION_RESULTS；
- ANOMALY_RECORDS；
- OPERATION_ACTIONS。

### 8.2 Filter 与 Snapshot

用户可根据 Catalog 返回的字段配置允许的筛选条件，并查看 `analysis_as_of` 对应的数据截点。前端不自行增加报告字段或解释筛选规则。

### 8.3 Preview

系统按 Schema 定义的列顺序展示报告预览，明确显示 Availability。预览不修改原始数据。

### 8.4 CSV/XLSX Export

用户确认后可下载 CSV 或 XLSX 文件。后端负责格式、安全转义、大小限制和 MIME；前端只接收 Blob 并触发浏览器下载。

CSV 支持 UTF-8 BOM、CRLF 和公式注入防护；XLSX 使用 write-only 方式生成。报告文件请求时生成，不在 V1.0 中长期保存。

## 9. 显式可用状态

Read Model、治理和报告模块使用显式 Availability 状态表达可用、部分可用、数据不足、空结果或不可用等情况。系统不使用 `None`、空白页面或数字 0 替代业务状态。

## 10. 功能边界声明

V1.0 不提供：

- AI 内容、AI Agent 或机器学习平台；
- 自动运营建议、推荐或自动决策；
- 因果推断；
- 自动数据修复；
- 报告异步任务、长期归档或下载审计；
- 尚无数据基础的 ROI、广告消耗、用户留存等指标。

申请材料和演示解说不得扩大上述范围。
